# ADR-0003 手写的 YAML 编辑器暂时不换掉

## 背景

设置页改完 Provider 之后，除了写数据库，还会把配置同步到 `~/.ai-interviewer/llm-providers.yml`。
写这个文件的地方是 `LlmProviderConfigService` 里的 `YamlTextEditor`（约 150 行）：`findKey`、`findSectionEnd`、
`indentOf`、`formatValue` 几个方法按行扫，找到键就改值，找不到就追加到 section 末尾。

当时手写而不是引库的原因：这个文件是给人看也给人改的，用户会在里面留言、调顺序、留注释。
用「解析 → 改 → 序列化」的写法则会把注释和顺序全部丢掉。

## 已知问题

它只认本项目自己写出去的那种形状：

- 只处理两空格缩进。用户在编辑器里改成四空格或 tab，键就找不到了，代码会追加一份重复的键。
- 只处理「顶层 section → 一层子键」的结构。子键下面再挂数组或对象时，`findSectionEnd` 会提前结束。
- 值里的 `#` 被当成注释起点，值里的引号不特殊处理。
- 改写只保留值，不保留行尾注释。

## 为什么现在不修

1. 它不是主路径。运行时读配置先读数据库，yaml 只是给「直接手改文件」的人留的兜底入口。
2. 换实现要引入 YAML 序列化依赖，且会重排用户手改过的文件——把一个「偶尔写错位置」的问题换成一个「文件被重排」的问题。
3. 现阶段更值得做的是语音链路和上传校验，这两块出错是功能不可用，这里是配置不生效且能看出来。

## 触发条件

出现下面任一情况就重写它：

- 有人反馈配置改了不生效、或者 yml 里出现重复键。
- 需要在 yml 里写数组或嵌套对象（比如多 provider 的模型列表）。
- 这套写文件的路径要暴露给更多用户，而不是本机单用户。

## 我放弃了什么

更稳的写法是 Jackson YAML + 手写注释保留（读成树、改节点、按原顺序输出，注释单独维护一张表），
代码量大约翻倍，能覆盖上面四个问题里的三个。现在选择不写，代价是这四个问题会一直在。修复前
`llm-providers.yml` 出问题，删掉整个文件重启即可重新生成——这一条没有写在设置页的提示里，属于欠的账。
